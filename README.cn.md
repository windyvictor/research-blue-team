# research-blue-team

[English](README.md) | 中文 · [Research Skillbox 总导航](https://github.com/windyvictor/research-skillbox)

科研 AI 蓝军。它挑战决定研究走向的主张——选题、实验、证明、论文、基金申请——并按「是否改变决定」校准每一条异议。目标是找到有依据的最强反例，不是攒出最长的意见清单。

本仓库是给智能体的说明，没有检查脚本、测试运行器或评分。一条异议不是放弃整条路线的决定。

## 解决什么问题

审查容易偏到两头：把力气花在措辞、编号和图表字号上，或者用一处缺口否定整条路线。[SKILL.md](SKILL.md) 把审查留在会改变当前决定的那条主张上。材料支持该主张时，技能写明支持，并说清核对了什么。

## 你会得到什么

交付取决于正在做的决定，以 [SKILL.md](SKILL.md) 为准：

| 正在决定什么 | 首先交付什么 |
|---|---|
| 科研想法是否值得做 | 最接近的已知结果或候选基线、真正新增的部分，以及一项能尽早决定去留的检验 |
| 实验能否检验核心假设 | 原解释与最强竞争解释会在哪个对照下给出不同结果，以及结果如何限制结论 |
| 论文结论能否成立、可以写到哪一步 | 定位到原句、定理、证明步骤、表格或图；给出反驳、修复，或证据支持的替换句 |
| 申请书能否支撑资助理由 | 决定该理由的科学问题、技术路线最关键的依赖、能证明可行性的前期证据，以及仍能回答原问题一部分的备选路径 |

书面审查给出判断、依据，以及一项足以改变判断的下一步。若要陪练，请直接说明：技能每轮只问一个问题并等待。你要求一次性意见，或当前无法逐轮回复时，它不进入问答。

## 何时使用，何时不用

在你要求蓝军、反例、评审预演，或核对实验是否真能说明主张时使用。组会追问、审稿追问和基金答辩同样适用。[SKILL.md](SKILL.md) 记录的触发语包括「当蓝军」「挑战我的想法」「找反例」「预演评审」「这个实验真能说明问题吗」。

这些任务不用它：

- 翻译、排版或语言润色。它们沿用原任务。要在保留事实、不确定性、引用和作者声音的前提下清理模板化表达，使用 [academic-deai-writing](https://github.com/windyvictor/academic-deai-writing)。
- 编号、图字号、参考文献格式。[references/calibration.md](references/calibration.md) 把它们视为可选或不报。
- 替作者决定做不做这个项目、重写全文，或把每条潜在审稿疑问都写进局限。
- 只凭摘要判断全文。判断停在摘要之内。
- 给申请书打分、推断资助方的隐含偏好，或估计资助概率。只有指南题名时，判断停在主题层面。

决定判断所需的材料缺失时，技能索取最小片段并等待。它不用猜测填补缺口。

## 定位与使用边界

[SKILL.md](SKILL.md) 里的立场是明确的。蓝军不是敌军，也不是叛军：和作者解决同一个科学问题，可以质疑当前路线，不改变研究目标。它先问什么证据会让双方改变判断。

下面是规则，不是语气要求：

- 只报会改变结论或决定的异议，每条都要有证据。
- 不凑条数。一轮最多三条独立异议。
- 反例必须满足全部前提并违反结论。成立时，它回答的是这条主张，并不因此关闭邻近主张或整条路线。
- 证明中的一步失效，只说明这条证明需要修补，并不因此说明定理为假。
- 两个因素同时改变时，先写出两种解释，再要一个能把它们分开的对照。
- 作者最强回应成立时撤回异议。不为了凑满清单换一个角度重开。
- 不把「简单」「显而易见」或「A+B」当成创新性不足。逐项比较假设与结论。
- 查新命中相近论文，不等于主张已经被做过，除非展示旧结果确实覆盖当前主张。
- 「可能」和「这里没有报告」不是「已证伪」或「作者没做」。

设计依据及其边界在 [references/sources.md](references/sources.md)。它们用来支持上面的刹车，不是用来证明更严厉的异议必然正确。

## 审查一轮

[SKILL.md](SKILL.md) 规定五步：

1. 用一句话写下要做的决定。保留对象、量词、前提和比较范围。只有摘要时，写明这一点。
2. 选出最可能改变决定的一条异议，并核对手头材料已经能够核的部分。
3. 在正文、附录或作者答复里找最强的回应。回应成立就撤回；只成立一部分时，指出剩下的问题。
4. 给出判断、依据和下一步。已经能够裁决的点，只给证据支持的局部修改。仍有两种可能时，给一项核查，并写明每种结果会改变什么。
5. 新材料到来时，指出它改变了上一轮判断的哪一步。问题解决，或没有新证据可查时停止。即使前几轮没有实质问题，新证据到来也要重新判断。

[references/calibration.md](references/calibration.md) 中任一刹车条件成立，就停止，不再补一条：最强回应已经成立、决定现在可以做、连续两轮没有新证据或可行核查、异议重复或来回改判、或者本轮已经到条数上限。停止时写本轮结论、已核实范围和未核实项。收束不了的分歧只留一条「待核实」。

## 质疑可以有多强

分级是内部优先级。默认用散文说明。需要看到字母等级时再要求。

| 级别 | 含义 | 允许的动作 |
|---|---|---|
| **A，已证实且影响结论** | 材料内的证据会改变某条核心结论，或改变读者对它的理解 | 收窄主张、补证明、改对照，或撤下某一句。只动这一处。 |
| **B，待核实** | 有具体疑点，现有材料不能裁决 | 一项低成本核查，并写明每种结果支持什么。不写成修改要求。 |
| **C，可选补强** | 不影响结论 | 收进一个从句，或省略。不写进局限性。 |

`PASS_NO_CHANGE` 是合法结果。没有 A 或 B 时，写明本轮未发现实质问题，并列出核对了什么、没核对什么。不要以「再补一条」收尾。

[references/calibration.md](references/calibration.md) 里有六类一出现就删除或降级的模式：枝节替代核心主张、放到一篇站得住的文章上仍然说得通的模板意见、凑数或转移话题、把简单当成缺乏创新、把猜测写成缺陷、以及替作者决定或重写。同一文件还有保留一条意见前要核对的证据字段、八项落笔前检查，以及供修改技能的人使用的六个回归用例。本仓库没有运行这些用例的脚本。

## 需要提供什么，会返回什么

给出刚好能检查这个决定的最小材料：

- 你即将做的决定。
- 主张本身，包括对象、量词、前提和比较范围。
- 你实际拥有的材料：摘要、选定章节、证明步骤、实验描述、表格或申请书段落。其余缺失时请说明。
- 要书面审查，还是一次只问一个问题。
- 赌注不是默认档时请说明：可改回的措辞、设计选择，或投稿、基金、大规模实验这类不可逆步骤。
- 保密或离线约束。
- 若要求改写，说明原意和记号保持不变。

若允许技能核对公开来源，不要自行把未发表的定理表述、项目标题、评审意见、数据或可识别片段贴进网页检索。技能自己的规则是只用公开题名、标准术语和已经公开的信息检索。

书面回复是这个形状：

| 部分 | 内容 |
|---|---|
| 决定与主张 | 一句话。只看摘要的工作停在摘要内。 |
| 判断 | 支持、收窄、需要核查，或本轮没有实质问题。 |
| 依据 | 能够定位的句子、公式、表格、计算或公开来源。 |
| 下一步 | A：一处局部修改。B：一项核查，以及每种结果意味着什么。没有实质异议：写明核对范围。 |
| 条数 | 独立异议最多三条。C 级通常不出现。 |

这段散文背后的内部核对是：位置、证据、哪条结论会动、最小动作、置信度。缺少能够定位的依据，就是舍弃该意见的理由。

## 可复制的调用

下面是提示词，不是已记录的模型回答。在 Codex CLI 或 IDE 扩展中，前缀 `$research-blue-team` 是显式点名。ChatGPT 桌面端按 [Build skills](https://learn.chatgpt.com/docs/build-skills) 用 `@` 选择技能。任务正文两边相同。

下面的具体情形是 [references/scenarios.md](references/scenarios.md) 里已经写好的例子，用来表明哪一种核查相关。它们不是本仓库测出的结果。

### 选题

```text
$research-blue-team
我想用新的邻域图识别稀疏簇。请按蓝军审查这个想法。把它改写成同行可以反驳的主张，指出最接近的已知结果或候选基线、真正新增的部分，以及一项能尽早决定去留的检验。我还没有结果时，不要判断做还是不做。相近论文只有在你展示其结果覆盖本主张时，才算削弱创新性。
```

[references/scenarios.md](references/scenarios.md) 用这个例子区分新的边权与仅仅减少跨簇边：在可控制密度和簇间距的合成数据上，与边数匹配的常规图比较，固定下游聚类方法，记录跨簇边比例和聚类误差。

### 实验

```text
$research-blue-team
方法同时改了邻域图和求解器，组合模型得分更高。请检查能否把增益归给图。写出原解释和最强的替代解释。给出一项能把二者分开的比较；在兼容的前提下固定求解器、数据划分和调参预算。没有这项比较时，不要把组合增益写成「新图提高了精度」。
```

同一份参考写明：较广的建图解释，需要新图在两个求解器下都改善。只在新求解器下改善，就先检查交互作用。某一组合不能运行时，写明哪一项效应无法辨认，并收窄主张。

### 理论证明

```text
$research-blue-team
我主张：连续、严格递减且有下界的目标函数，一定在实线上取得最小值。请检查这一步。反例必须满足全部前提并违反结论。若反例只否定「取得最小值」，请说明主张应收到哪一步。若后续步骤需要极小点，不要把所缺条件写成我已经证明的事实。
```

[references/scenarios.md](references/scenarios.md) 中的例子是 `exp(-x)`：三项前提都成立，下确界为零，函数值始终为正。这否定「取得最小值」。它不否定只需要下确界存在的主张。

### 论文

```text
$research-blue-team
下面是标题、摘要、引言句子和结果段。请找出结论在哪一步超过证据，并指向句子、定理、表格或图。如果我只检验了预先指定的扰动，有依据的句子就限于已检验的扰动。不要报告格式、编号、图字号或参考文献样式。如果我要求改写，保持原意和记号，只改证据支持的那一句。
```

### 基金

```text
$research-blue-team
这份申请书把强凸条件下证明的收敛结果推广到更一般的模型。请一次只问一个问题来预演答辩，并等我回答。从承载资助理由的科学问题开始。追问原证明第一次实质使用强凸性的地方，以及拟引入的条件是否补回那一步所提供的性质。不要编造评分、评审偏好或资助概率。
```

[references/scenarios.md](references/scenarios.md) 写明：前期结果只支持收敛到解集时，把全局线性速率留作待解决目标，并说明较弱的备选路线仍能回答原问题的哪一部分。

## 轻度、中度、重度

赌注改变查多深，不提高三条异议的上限。三档都使用上面的分级。重度不是允许在没有刹车的情况下继续反对。

| 档 | 用于 | 查什么 |
|---|---|---|
| 轻度 | 可以改回的选择，例如摘要中的一句话，或组会口径 | 关键事实、量词和适用范围 |
| 中度，默认 | 要不要补做一个实验，或走哪条技术路线 | 关键假设、竞争解释、最强基线和证据链 |
| 重度 | 不可逆或高后果步骤：投稿、基金、开题答辩或大规模实验 | 中度的全部内容，再加上失败预演、对最强论证施压，以及备用路线 |

重度档开始前，先写下什么证据会让质疑停止，并只攻一个可能改变决定的点。[references/calibration.md](references/calibration.md) 警告不要做指定的唱反调：没有裁决证据的持续否定，会让双方更坚持原判断。

## 与其他技能配合

这些是各自独立的仓库。本技能不调用它们。另一项技能做它自己写明的工作，本技能再做会改变决定的质疑。

| 工作 | 使用 | 本技能仍然做什么 |
|---|---|---|
| 阅读论文并标出实际读过的范围 | [paper-deep-reading](https://github.com/windyvictor/paper-deep-reading) | 只在该材料边界内挑战主张 |
| 建立证明、设计、算法或实验 | [research-copilot](https://github.com/windyvictor/research-copilot) | 挑战会改变决定的主张。它不代替推导或实验方案 |
| 依据可追溯证据起草或修改论文 | [writing-research-papers](https://github.com/windyvictor/writing-research-papers) | 定位结论在哪里超过证据。改写保持局部，并保留有依据的主张 |
| 按当年指南起草基金论证 | [grant-proposal-ai](https://github.com/windyvictor/grant-proposal-ai) | 挑战决定资助理由的依赖。合规仍按该技能的当年指南核对 |
| 去掉模板化表达且不改变科学内容 | [academic-deai-writing](https://github.com/windyvictor/academic-deai-writing) | 措辞、语气和披露要求留在那里 |

一次蓝军审查不为其他技能的产出背书。语气客气或严厉也不改变等级。

## 隐私与局限

[SKILL.md](SKILL.md) 沿用你对未发表论文、申请书和数据设定的保密要求。它只在当前授权范围内处理材料。公开核对使用公开题名、标准术语和已经公开的信息。离线意味着只用所给材料，并把缺少的外部比较写成缺少。

[references/sources.md](references/sources.md) 和 [references/calibration.md](references/calibration.md) 里的边界是结果的一部分：

- 所引实证研究来自 LLM 评审、代码批评和元科学。这些任务与数学、优化或机器学习论文不是同一分布。引用用来支持刹车，不是用来主张某一类异议永远正确或永远错误。
- 事前验尸和 Rapoport 规则是思维框架。本技能采用其中能够核对的测试和停止规则。它不主张这种姿态本身会让批评更有效。
- 严格评审与后续引用之间的报告关联是观察性的，样本是已接收论文。不能据此期望一次更严的审查会提高某一篇稿件的影响力。
- 真正投稿时，以目标期刊当年的审稿指南为准。

## 安装与调用

克隆后做符号链接，这是其他独立技能使用的安装写法，包括 [research-copilot](https://github.com/windyvictor/research-copilot)、[writing-research-papers](https://github.com/windyvictor/writing-research-papers) 和 [paper-deep-reading](https://github.com/windyvictor/paper-deep-reading)。目标目录是当前 Codex 技能文档 [Build skills](https://learn.chatgpt.com/docs/build-skills) 中的用户技能位置：`$HOME/.agents/skills`。该页同时写明 Codex 会跟随指向技能目录的符号链接。

```bash
git clone https://github.com/windyvictor/research-blue-team.git
mkdir -p ~/.agents/skills
ln -s "$PWD/research-blue-team" ~/.agents/skills/research-blue-team
```

`mkdir` 只是为了在创建链接前让文档中的目录存在。若只给一个仓库使用，改为把本目录放在 `.agents/skills/research-blue-team`。Codex 从启动时所在目录向上扫描到仓库根的 `.agents/skills`。同一页写明，它不会合并两个 `name` 相同的技能，两者都可能出现。

[SKILL.md](SKILL.md) 中的 `name` 是 `research-blue-team`。[agents/openai.yaml](agents/openai.yaml) 把 Codex 显示名设为「科研 AI 蓝军」，并保存这段默认提示：

```text
请用 $research-blue-team 检查这份研究材料最关键的主张，提出最强异议，说明依据和影响，给出能改变判断的最小验证；没有实质问题就直接说明。
```

同一份 Codex 文档还说明：

- 在 Codex CLI 或 IDE 扩展中，运行 `/skills`，或输入 `$research-blue-team`。
- 在 ChatGPT 桌面端，输入 `@` 并选择技能。
- 本仓库的 `agents/openai.yaml` 没有设置 `policy.allow_implicit_invocation`。文档默认值是 `true`，因此与 `SKILL.md` 的 `description` 相配的提示可能不写 `$` 也会选中该技能。显式的 `$research-blue-team` 仍然有效。把该策略设为 `false` 会关闭隐式选择；本仓库没有这样设置。
- Codex 会自行发现技能变化。安装或修改没有出现时，重启 Codex。
- 要停用而不删除技能，该页给出 `~/.codex/config.toml` 中的 `[[skills.config]]` 条目，写上 `SKILL.md` 路径和 `enabled = false`。

这次安装遵循该页记载的 `$HOME/.agents/skills`，不安装到较旧的 `~/.codex/skills`。其他智能体宿主使用自己的技能目录。WorkBuddy 从技能目录读取 `SKILL.md`。
